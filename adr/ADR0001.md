# ADR0001: PostgreSQL Database Schema, Constraints & Docker Service

## Status
Accepted

## Context
In ADR0000, we established the project layout and architecture foundation.
Now, we must define the relational data model in PostgreSQL to support all features of the EOS management product according to the assessment brief:
- **Core Entities**: Companies, Teams, Users, Team Memberships, Measurables, Scores, Rocks, Milestones, Issues, To-Dos, Meetings, Meeting Attendees, and Meeting Ratings.
- **Data Integrity (Section 2.7)**: Database constraints must reject invalid data at the database layer, not only in application code.
- **Source Linking (Section 2.2 & 2.8)**:
  - An Issue can be created directly OR linked to an off-track Measurable score (a specific `measurable_id` and `week_start`).
  - A To-Do can be created directly OR linked to a source Issue (`source_issue_id`).
- **Idempotency & Concurrent Safety (Section 2.6 & 2.8)**:
  - "Make it an Issue" must not produce duplicate unsolved issues for the same Measurable and week, even under concurrent requests.
- **Time Representation**: All timestamps stored in UTC (`TIMESTAMP WITH TIME ZONE`). Dates without a time (such as `due_date` or `week_start`) stored as `DATE`.
- **Developer Experience**: Provide a one-command Docker Compose setup for PostgreSQL (`docker-compose.db.yml` and root integration) along with one-click migration and reset scripts so that developers can easily run and manage the database.

## 1. Database Schema Design

### 1.1 `companies`
Stores company-level metadata and operating timezone.
- `id` (VARCHAR PRIMARY KEY, e.g. `'co_1'`)
- `name` (VARCHAR NOT NULL)
- `timezone` (VARCHAR NOT NULL DEFAULT `'America/Chicago'`)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.2 `teams`
Represents leadership, sales, ops, etc.
- `id` (VARCHAR PRIMARY KEY, e.g. `'team_lead'`)
- `company_id` (VARCHAR NOT NULL REFERENCES `companies(id)` ON DELETE CASCADE)
- `name` (VARCHAR NOT NULL)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.3 `users`
Company-wide users with global roles.
- `id` (VARCHAR PRIMARY KEY, e.g. `'u1'`)
- `company_id` (VARCHAR NOT NULL REFERENCES `companies(id)` ON DELETE CASCADE)
- `name` (VARCHAR NOT NULL)
- `email` (VARCHAR NOT NULL UNIQUE)
- `role` (VARCHAR NOT NULL CHECK (`role` IN ('admin', 'team_member', 'observer')))
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.4 `team_memberships`
Many-to-many relationship mapping users to teams.
- `id` (SERIAL PRIMARY KEY)
- `user_id` (VARCHAR NOT NULL REFERENCES `users(id)` ON DELETE CASCADE)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint**: `UNIQUE(user_id, team_id)`

### 1.5 `measurables`
Weekly KPIs with goals.
- `id` (VARCHAR PRIMARY KEY, e.g. `'m1'`)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `owner_id` (VARCHAR NOT NULL REFERENCES `users(id)`)
- `name` (VARCHAR NOT NULL)
- `unit` (VARCHAR NOT NULL, e.g. `'count'`, `'%'`, `'hours'`, `'$k'`)
- `goal_type` (VARCHAR NOT NULL CHECK (`goal_type` IN ('at_least', 'at_most', 'between', 'exactly')))
- `goal_value` (NUMERIC NULL) — for `'at_least'`, `'at_most'`, `'exactly'`
- `goal_min` (NUMERIC NULL) — for `'between'`
- `goal_max` (NUMERIC NULL) — for `'between'`
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint**:
  - `CHECK ((goal_type != 'between' AND goal_value IS NOT NULL) OR (goal_type = 'between' AND goal_min IS NOT NULL AND goal_max IS NOT NULL AND goal_min <= goal_max))`

### 1.6 `scores`
Weekly values recorded for a measurable.
- `id` (SERIAL PRIMARY KEY)
- `measurable_id` (VARCHAR NOT NULL REFERENCES `measurables(id)` ON DELETE CASCADE)
- `week_start` (DATE NOT NULL) — Monday date of the week (company time)
- `value` (NUMERIC NOT NULL)
- `updated_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint**: `UNIQUE(measurable_id, week_start)`

### 1.7 `rocks`
Quarterly 90-day priorities.
- `id` (VARCHAR PRIMARY KEY, e.g. `'r1'`)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `owner_id` (VARCHAR NOT NULL REFERENCES `users(id)`)
- `title` (VARCHAR NOT NULL)
- `quarter` (VARCHAR NOT NULL, e.g. `'2026-Q4'`)
- `status` (VARCHAR NOT NULL CHECK (`status` IN ('on_track', 'off_track', 'complete')))
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.8 `milestones`
Dated steps toward a Rock.
- `id` (VARCHAR PRIMARY KEY, e.g. `'ms1'`)
- `rock_id` (VARCHAR NOT NULL REFERENCES `rocks(id)` ON DELETE CASCADE)
- `title` (VARCHAR NOT NULL)
- `due_date` (DATE NOT NULL)
- `done` (BOOLEAN NOT NULL DEFAULT FALSE)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.9 `issues`
Problems raised, prioritized 1 to 5, and worked through IDS.
- `id` (VARCHAR PRIMARY KEY, e.g. `'i1'`)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `owner_id` (VARCHAR NOT NULL REFERENCES `users(id)`)
- `title` (VARCHAR NOT NULL)
- `priority` (INTEGER NULL CHECK (`priority` BETWEEN 1 AND 5))
- `source_measurable_id` (VARCHAR NULL REFERENCES `measurables(id)` ON DELETE SET NULL)
- `source_week_start` (DATE NULL)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- `solved_at` (TIMESTAMPTZ NULL)
- `resolution_note` (TEXT NULL)
- **Constraints**:
  - `CHECK ((source_measurable_id IS NULL AND source_week_start IS NULL) OR (source_measurable_id IS NOT NULL AND source_week_start IS NOT NULL))`
  - `CHECK (solved_at IS NULL OR (solved_at IS NOT NULL AND resolution_note IS NOT NULL))`
  - **No Duplicate Unsolved Issues Index**:
    `CREATE UNIQUE INDEX uq_unsolved_source_issue ON issues (source_measurable_id, source_week_start) WHERE solved_at IS NULL AND source_measurable_id IS NOT NULL;`
    *(Ensures concurrent "Make it an Issue" requests for the same measurable & week cannot insert duplicates).*

### 1.10 `todos`
Action items resulting from solving issues or meeting recaps.
- `id` (VARCHAR PRIMARY KEY, e.g. `'t1'`)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `owner_id` (VARCHAR NOT NULL REFERENCES `users(id)`)
- `source_issue_id` (VARCHAR NULL REFERENCES `issues(id)` ON DELETE SET NULL)
- `title` (VARCHAR NOT NULL)
- `due_date` (DATE NOT NULL)
- `done_at` (TIMESTAMPTZ NULL)
- `created_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())

### 1.11 `meetings`
Weekly Level 10 meetings.
- `id` (VARCHAR PRIMARY KEY, e.g. `'mt1'`)
- `team_id` (VARCHAR NOT NULL REFERENCES `teams(id)` ON DELETE CASCADE)
- `facilitator_id` (VARCHAR NOT NULL REFERENCES `users(id)`)
- `started_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- `ended_at` (TIMESTAMPTZ NULL)
- `current_section` (VARCHAR NOT NULL DEFAULT 'scorecard' CHECK (`current_section` IN ('scorecard', 'ids', 'conclude', 'ended')))
- `section_started_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint (One active meeting per team)**:
  `CREATE UNIQUE INDEX uq_active_team_meeting ON meetings (team_id) WHERE ended_at IS NULL;`

### 1.12 `meeting_attendees`
Tracks who joined the meeting.
- `meeting_id` (VARCHAR NOT NULL REFERENCES `meetings(id)` ON DELETE CASCADE)
- `user_id` (VARCHAR NOT NULL REFERENCES `users(id)` ON DELETE CASCADE)
- `joined_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint**: `PRIMARY KEY (meeting_id, user_id)`

### 1.13 `meeting_ratings`
Ratings submitted by attendees in the Conclude section (1 to 10).
- `meeting_id` (VARCHAR NOT NULL REFERENCES `meetings(id)` ON DELETE CASCADE)
- `user_id` (VARCHAR NOT NULL REFERENCES `users(id)` ON DELETE CASCADE)
- `rating` (INTEGER NOT NULL CHECK (`rating` BETWEEN 1 AND 10))
- `updated_at` (TIMESTAMPTZ NOT NULL DEFAULT NOW())
- **Constraint**: `PRIMARY KEY (meeting_id, user_id)`

## 2. Docker Compose & Database Automation

1. **PostgreSQL Docker Service (`docker-compose.db.yml`)**:
   - Containerized PostgreSQL 16 image.
   - Volume persistence (`pgdata_track`) to preserve data across restarts.
   - Healthcheck using `pg_isready -U postgres -d track_db`.
   - Exposed on standard port `5432`.
2. **Database Management Scripts**:
   - `backend/scripts/start_db.sh`: Spins up PostgreSQL container in detached mode and waits until it is fully ready.
   - `backend/scripts/stop_db.sh`: Stops the PostgreSQL container.
   - `backend/scripts/run_migrations.sh`: Runs Alembic migrations to apply/update schema.
   - `backend/scripts/reset_db.sh`: Drops and recreates the schema cleanly for fresh test runs.

## 3. Best Practices Implemented

1. **Declarative Models (SQLAlchemy 2.0)**: Clean, typed model definitions matching the schema exactly.
2. **Partial Unique Indexes**: Used for concurrency-safe duplicate prevention and active meeting constraints.
3. **Database-Level Integrity Constraints**: Reject invalid states at the Postgres level.
4. **Transparent Documentation**: Updated `HOW_TO_RUN.md` with simple step-by-step instructions for non-expert operators.
