# ADR0002: Time, Timezone & Simulated Clock (APP_NOW) Architecture

## Status
Accepted

## Context
Per the assessment specification (Sections 2.6 & 2.7):
- **Timestamps**: All database timestamps must be stored in UTC (`TIMESTAMPTZ`).
- **Simulated Clock**: The application must read "now" from the `APP_NOW` environment variable (default: `2026-11-11T15:00:00Z` - Wednesday, Nov 11, 2026, 9:00 AM Chicago time), rather than using the system host clock.
- **Company Timezone**: Acme Logistics operates in `America/Chicago`.
- **Week Boundaries**: A week runs from Monday 00:00:00 to Sunday 23:59:59 in company time. Weeks are identified by their Monday date (`week_start`, e.g. `2026-11-02`).
- **Calendar Dates**: Due dates and milestones are calendar dates without time (`YYYY-MM-DD`) in company time.
- **Overdue Definition**: A To-Do is overdue when `done_at IS NULL` and its `due_date < today` (where "today" is the date of `APP_NOW` in company time: `2026-11-11`). A milestone due today is *not* past due.
- **Last Closed Week**: The full Monday–Sunday week before the current week (for `APP_NOW = 2026-11-11`, the current week is `2026-11-09`, and the last closed week is `2026-11-02`).
- **Quarter Calculation**: Standard calendar quarters (Q1: Jan-Mar, Q2: Apr-Jun, Q3: Jul-Sep, Q4: Oct-Dec) based on the date of `APP_NOW` in company time.

We need a dedicated, deterministic, and testable domain clock service that handles all time calculations uniformly across the backend and rules engine.

---

## 1. Domain Clock Design (`app/core/clock.py`)

We will expand `app/core/clock.py` to provide the following pure functions:

### 1.1 Core Clock Primitive
- `get_app_now(override_iso: Optional[str] = None) -> datetime`:
  - Returns timezone-aware UTC datetime.
  - Priority: parameter `override_iso` $\rightarrow$ `os.environ.get("APP_NOW")` $\rightarrow$ `settings.APP_NOW` $\rightarrow$ `2026-11-11T15:00:00Z`.

### 1.2 Timezone Conversion & "Today"
- `get_company_timezone() -> ZoneInfo / pytz`:
  - Returns `ZoneInfo("America/Chicago")` (or `pytz.timezone`).
- `get_app_now_company(now_utc: Optional[datetime] = None) -> datetime`:
  - Converts the UTC now into `America/Chicago` local datetime.
- `get_today_company(now_utc: Optional[datetime] = None) -> date`:
  - Returns the calendar date of `APP_NOW` in `America/Chicago` (e.g. `2026-11-11`).

### 1.3 Week Calculations (Monday to Sunday)
- `get_week_start(d: Union[date, datetime]) -> date`:
  - Given any date/datetime in company time, returns the Monday date of that week (`d - timedelta(days=d.weekday())`).
- `get_week_range(week_start: date) -> Tuple[datetime, datetime]`:
  - Returns start: `Monday 00:00:00` and end: `Sunday 23:59:59.999999` in `America/Chicago` converted to UTC timestamps for DB querying.
- `get_current_week_start(now_utc: Optional[datetime] = None) -> date`:
  - Returns the Monday of the current week (for `2026-11-11`, returns `2026-11-09`).
- `get_last_closed_week_start(now_utc: Optional[datetime] = None) -> date`:
  - Returns the Monday of the preceding closed week (`current_week_start - 7 days`, for `2026-11-11`, returns `2026-11-02`).
- `get_13_weeks_range(current_week: date) -> List[date]`:
  - Returns a list of 13 consecutive Monday dates ending with `current_week` (for default `APP_NOW`: `2026-08-17` to `2026-11-09`).

### 1.4 Quarter & Overdue Checks
- `get_current_quarter(d: Union[date, datetime]) -> str`:
  - Returns e.g. `'2026-Q4'`.
- `is_overdue(due_date: date, done_at: Optional[datetime], now_utc: Optional[datetime] = None) -> bool`:
  - Returns `True` iff `done_at is None` and `due_date < get_today_company(now_utc)`.

## 2. Testing Strategy
- Unit tests in `backend/tests/test_clock.py` testing:
  1. Default `APP_NOW` resolution (`2026-11-11T15:00:00Z` $\rightarrow$ 9:00 AM Chicago).
  2. Overriding `APP_NOW` dynamically for arbitrary testing dates.
  3. Boundary cases (Sunday 23:59:59 vs Monday 00:00:00 transition in Chicago).
  4. 13-week sequence generation matching the seed data range exactly (`2026-08-17` through `2026-11-09`).
  5. Due date comparison (`due_date == today` is NOT overdue; `due_date == today - 1` is overdue).
