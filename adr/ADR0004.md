# ADR0004: Domain Business Rules Engine

## Status
Accepted

## Context
Per Section 2.6 of the assessment brief, the product must implement a set of exact business rules that are checked directly against the seed data and evaluation tests:
1. **Rounding Rule**:
   - Round half up (`12.5%` $\rightarrow$ `13%`, `8.25` $\rightarrow$ `8.3`).
2. **Measurable Status (`on_track` | `off_track` | `pending`)**:
   - Compare week's score with the goal: `at_least`, `at_most`, `between`, `exactly`.
   - Boundaries are `on_track` (e.g. goal `at_least 10` with score `10` is on track; `between 2 and 4` with `2` or `4` is on track).
   - A closed week (any week before the current week) with no score is `off_track`.
   - The current week (or future) with no score is `pending`.
3. **To-Do Completion Rate**:
   - `To-Dos done by the end of a week ÷ To-Dos due that week`.
   - A week runs Monday 00:00:00 to Sunday 23:59:59 in company time (`America/Chicago`).
   - "Done by the end of a week": `done_at <= week_end_utc`.
   - "Due that week": `due_date >= week_start AND due_date <= week_end`.
   - Done *after* its due week counts as *not done* for that due week.
   - Target is `90%`.
   - `meets_target` compares the exact ratio $\ge 0.90$, not the rounded percent.
   - Zero due means `null` (no rate).
4. **Rock Status (`on_track` | `off_track` | `complete`)**:
   - If seeded status is `complete` $\rightarrow$ `complete`.
   - If seeded status is `off_track` $\rightarrow$ `off_track`.
   - If an unfinished milestone (`done == False`) has `due_date < today` $\rightarrow$ `off_track`.
   - A milestone due today is *not* past due (`due_date == today` is safe).
   - If no milestones $\rightarrow$ seeded status alone.
   - Otherwise $\rightarrow$ `on_track`.
5. **Rock Progress**:
   - `Completed Milestones ÷ Total Milestones`, as a whole percent rounded half up (`round_half_up(done / total * 100)`).
   - If no milestones: `0%`, or `100%` once `complete`.
6. **Issue Order (Sorting Algorithm)**:
   - Priority 5 first, down to 1 (`priority DESC`).
   - Within same priority, oldest first (`created_at ASC`).
   - No priority (`priority IS NULL`) comes last (`NULLS LAST`), sorted oldest first (`created_at ASC`).
7. **Meeting Rating**:
   - Average of submitted ratings, rounded half up to one decimal place.
   - Attendees who didn't rate are excluded.
   - If no attendees rated $\rightarrow$ `null`.

We must implement these rules as a clean, pure Python domain engine (`backend/app/domain/rules.py`) with zero framework coupling, making it simple to test, maintain, and reuse across both the REST API and the upcoming Rules Report command (ADR0005).

## 1. Domain Rules Architecture (`app/domain/rules.py`)

### 1.1 Pure Rounding Helper
```python
from decimal import Decimal, ROUND_HALF_UP

def round_half_up(val: Union[float, Decimal], decimals: int = 0) -> Union[int, float]:
    d = Decimal(str(val))
    target = Decimal("1") if decimals == 0 else Decimal("10") ** -decimals
    rounded = d.quantize(target, rounding=ROUND_HALF_UP)
    return int(rounded) if decimals == 0 else float(rounded)
```

### 1.2 Rule Evaluators
- `compute_measurable_status(goal_type: str, goal_val: Optional[Decimal], goal_min: Optional[Decimal], goal_max: Optional[Decimal], score_val: Optional[Decimal], is_closed_week: bool) -> str`:
  - Returns `'on_track'`, `'off_track'`, or `'pending'`.
- `compute_todo_completion_rate(todos_due_in_week: List[Todo], week_start: date) -> Optional[dict]`:
  - Returns `None` if zero due.
  - Otherwise returns `{"due": int, "done": int, "rate_percent": int, "meets_target": bool}`.
- `compute_rock_status_and_progress(rock: Rock, today: date) -> Tuple[str, int]`:
  - Returns `(status, progress_percent)`.
- `sort_issues(issues: List[Issue]) -> List[Issue]`:
  - Sort key: `(0 if p is not None else 1, -(p or 0), created_at)`.
- `compute_meeting_rating(ratings: List[int]) -> Optional[float]`:
  - Returns average to 1 decimal place or `None`.

## 2. Testing Strategy (`backend/tests/test_rules.py`)
- Unit test suite testing each of the 6 rules with explicit boundary and edge cases:
  1. **Measurable Boundaries**:
     - `at_least 10`: score `10` (on_track), `9.99` (off_track).
     - `between 2 and 4`: score `2` (on_track), `4` (on_track), `1.99` (off_track), `4.01` (off_track).
     - Missing score in closed week $\rightarrow$ `off_track`.
     - Missing score in current week $\rightarrow$ `pending`.
  2. **To-Do Rate**:
     - 9 due, 8 done $\rightarrow$ ratio $8/9 = 88.88\% \rightarrow$ `89%`, `meets_target: False`.
     - 10 due, 9 done $\rightarrow$ ratio $9/10 = 90.0\% \rightarrow$ `90%`, `meets_target: True`.
     - Completed after due week $\rightarrow$ counted as not done.
     - 0 due $\rightarrow$ `None`.
  3. **Rock Status & Progress**:
     - Milestone due today $\rightarrow$ NOT past due.
     - Milestone due yesterday $\rightarrow$ past due $\rightarrow$ `off_track`.
     - Progress: 1 of 3 done $\rightarrow$ `33%`; 0 of 0 milestones complete $\rightarrow$ `100%`.
  4. **Issue Order**:
     - Priority 5 before Priority 4.
     - Priority 5 created 10:00 before Priority 5 created 11:00.
     - Null priority always sorted to the end.
  5. **Meeting Rating**:
     - `[8, 9, 7]` $\rightarrow$ `8.0`.
     - `[8, 9, 8, 8]` $\rightarrow$ `8.3` (average 8.25 rounded half up).
     - Empty ratings $\rightarrow$ `None`.
