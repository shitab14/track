# ADR0005: Rules Report CLI Command (rules_report.json)

## Status
Accepted

## Context
Per Part 3 of the assessment brief and `task_resources/README.md`:
> *"A rules report: one documented command that prints every computed value in 2.6 for a freshly seeded database as JSON, in the format in the zip's README. We'll also run it at other dates, so compute every value from the data. Commit its output as rules_report.json."*

The rules report command is an automated deliverable used by Altri evaluators to verify the correctness of all business rules against an answer key for any given `APP_NOW`.

### Required Output Format (`task_resources/README.md`):
```json
{
  "now": "<APP_NOW, ISO 8601 UTC>",
  "teams": {
    "<team_id>": {
      "measurable_status": {"<measurable_id>": {"<week_start>": "on_track | off_track | pending"}},
      "todo_completion": {"<week_start>": "null, or {due, done, rate_percent, meets_target}"},
      "overdue_todos": ["<todo_id>"],
      "rocks": {"<rock_id>": {"status": "on_track | off_track | complete", "progress_percent": 0}},
      "issue_order": ["<issue_id>"],
      "meetings": {
        "<meeting_id>": {
          "scorecard_week": "<week_start>",
          "measurable_status": {"<measurable_id>": "on_track | off_track | pending"},
          "issues_solved": ["<issue_id>"],
          "todos_created": ["<todo_id>"],
          "attendee_ids": ["<user_id>"],
          "rating": "number with one decimal, or null"
        }
      }
    }
  }
}
```

### Key Technical Specifications for the Generator:
1. **Dynamic Clock Support**:
   - Must evaluate for the current `APP_NOW` (reading from `os.environ.get("APP_NOW")` or default `2026-11-11T15:00:00Z`).
   - "Today" is the calendar date of `APP_NOW` in company time (`America/Chicago`).
2. **Measurable Status Range**:
   - Include every team, and every Measurable belonging to that team with all **13 weeks ending with the current week** (e.g. `2026-08-17` to `2026-11-09` at default `APP_NOW`).
3. **To-Do Completion Range**:
   - Include each of those exact 13 weeks in `todo_completion`.
   - A week with nothing due must be literal `null`.
   - Weeks with tasks due must be `{"due": int, "done": int, "rate_percent": int, "meets_target": bool}`.
4. **Lists and Sorting**:
   - `overdue_todos`: Plain string sort (`t12` before `t30`).
   - `issue_order`: Strictly unsolved Issues in EOS Issue order (P5 $\rightarrow$ P1, oldest first, null priority last).
   - In meetings: `issues_solved`, `todos_created`, `attendee_ids` are sorted as plain strings.
5. **Meeting Summaries**:
   - Covers ended meetings (e.g., seeded `mt1` and `mt2`).
   - `scorecard_week`: The last closed week as of the meeting's `started_at` in company time.
   - `measurable_status`: Status of each team measurable for that `scorecard_week`.
   - `issues_solved`: Issues where `solved_at` fell within the meeting window (`started_at <= solved_at <= ended_at`).
   - `todos_created`: To-Dos where `created_at` fell within the meeting window (`started_at <= created_at <= ended_at`).
   - `rating`: Average of submitted ratings to 1 decimal place, or `null`.

## 1. Architecture & Implementation Design

### 1.1 Pure Domain Generator (`backend/app/domain/report.py`)
We will create a service that queries the database using SQLAlchemy and passes data into our pure rules engine (`app.domain.rules`):
```python
def generate_rules_report(db: Session, now_utc: Optional[datetime] = None) -> dict:
    ...
```
- Completely decoupled from CLI printing, returning the pure Python dictionary matching the required JSON schema.
- Reusable both by the CLI command and by API endpoints (e.g., `GET /api/v1/rules-report`).

### 1.2 CLI Command (`backend/app/cli/rules_report.py`)
- Python entrypoint: `python -m app.cli.rules_report`
- Accepts an optional `--app-now` argument to override the clock for ad-hoc evaluations.
- Prints indented, valid JSON to stdout.

### 1.3 Standalone Bash Runner (`backend/scripts/rules_report.sh`)
- Executable script: `./backend/scripts/rules_report.sh`
- Activates virtualenv and runs the generator.
- Easy for the evaluator to execute unattended with one documented command.

### 1.4 Baseline Artifact (`rules_report.json`)
- Generates and commits `rules_report.json` computed on a freshly seeded database at the default `APP_NOW` (`2026-11-11T15:00:00Z`).

## 2. Verification & Testing Strategy
- Unit test in `backend/tests/test_report.py`:
  1. Generate report on seeded database.
  2. Validate complete JSON structure against schema types.
  3. Validate specific known values:
     - 13 weeks present in `measurable_status` and `todo_completion`.
     - `mt1` and `mt2` correctly present in `team_lead.meetings`.
     - `mt1` rating is `8.0` (ratings: 8, 9, 7).
     - `mt2` rating is `8.5` (ratings: 8, 9, 8, 8 -> sum 33/4 = 8.25 -> 8.3).
     - `overdue_todos` and `issue_order` match expected ids.
