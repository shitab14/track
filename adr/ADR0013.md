# ADR0013: Automated Test Suite & Two-Browser Playwright E2E

## Status
Accepted

> **Stage 1 resolution.** (1) Playwright lives in `frontend/e2e/` (Chromium, trace
> on failure). (2) `scripts/test_all.sh` orchestrates pytest + Playwright now;
> `docker compose` packaging stays in ADR0014. (3) Failure artifact via a
> deliberate failing spec + trace-on-failure. All recommendations approved.
>
> **Execution note.** Per the user's instruction, the Chromium browser binary is
> not downloaded in this session, so the E2E and the trace are not executed or
> committed here; everything is wired and documented to run after
> `npx playwright install chromium`.

## Context

Part 3 requires that tests run unattended from one documented command, against
the seed data and a fixed clock, covering three layers:
- **Rule tests** — every rule in 2.6 with at least one boundary case.
- **API tests** — a Team Member reading another team's data is refused, an
  Observer write is refused, and concurrent Make-it-an-Issue requests return one
  Issue.
- **End-to-end** — one Playwright test with two browsers where the facilitator
  advances the agenda and the second browser follows.
Plus a short note on the fixture/clock strategy and one failure artifact (such as
a Playwright trace).

Most of this already exists and passes (54 backend tests):
- `test_rules.py` exercises each 2.6 rule with boundaries (measurable status
  across `at_least/at_most/between/exactly` incl. boundary/closed/pending,
  round-half-up, To-Do rate incl. the 90% boundary and done-after-due, Rock
  status/progress incl. milestone-due-today, Issue order incl. no-priority-last,
  meeting rating incl. excluded non-ratings).
- `test_rbac.py` and `test_concurrency.py` cover the exact API cases: cross-team
  read refused (403), Observer write refused (403), and concurrent promotion
  returning a single Issue (a real PostgreSQL thread race).

What is missing is the **two-browser Playwright E2E**, a **single documented
command** that runs all layers unattended, and a committed **failure artifact**.

## Decision

### 1. Keep the backend layers; audit and label them
Treat the existing pytest suite as the Rule and API layers. Audit `test_rules.py`
against the 2.6 table and add any missing boundary (e.g. an explicit
"current week with no score → pending" and "zero due → no rate" assertion if not
already present). No restructuring; these pass and are the answer-key coverage.

### 2. Playwright in the frontend package
Add `@playwright/test` as a frontend dev dependency with `frontend/playwright.config.ts`
and specs under `frontend/e2e/`. Chromium only (one browser engine, two
contexts, is what the spec asks). Config: `trace: "retain-on-failure"`,
`screenshot`/`video` on failure, a single worker (the meeting mutates shared
state), and a `webServer` that reuses the running frontend or starts
`npm run dev`.

### 3. The two-browser real-time test
`frontend/e2e/meeting-sync.spec.ts` opens **two isolated browser contexts** and
sets each one's seeded user deterministically via `addInitScript` writing
`track_user_id` (no clicking through the switcher): a **facilitator** (`u4`) and
an **attendee** (`u8`), both Team Members of `team_ops`.
- Facilitator navigates to the meeting route and clicks **Start Level 10
  Meeting**.
- Attendee navigates to the same route, sees the active meeting and joins.
- Facilitator clicks **→ IDS**.
- **Assert the attendee's page reaches the IDS section within ~2s** (navigator
  shows IDS active / the Issues section renders) — the section changes only via
  the SSE push, so this proves cross-browser real-time sync.
- Teardown: the facilitator **ends** the meeting (and a `beforeEach` clears any
  `team_ops` meeting via the API), so the one-active-meeting constraint never
  blocks a re-run.
A second, lightweight assertion confirms an **Observer** (`u7`, switched into
`team_sales`) sees the meeting read-only with no Start control.

### 4. One documented command, unattended
`scripts/test_all.sh` runs the whole suite against the seeded stack on the fixed
clock:
1. ensure Postgres is up and seeded (reuse `start_db.sh` + `seed_db.sh`);
2. run `pytest` (rule + API layers);
3. ensure the backend and frontend are up (reuse the run scripts);
4. run `npx playwright test` (E2E).
`HOW_TO_RUN.md` documents it as the single test command. `APP_NOW` stays at its
default `2026-11-11T15:00:00Z`, so every layer sees the same fixed clock.

### 5. Fixture & clock strategy (documented)
- **Unit/rule and pure service tests** run on an isolated, freshly seeded
  in-memory SQLite database (the idempotent seeder), fully deterministic.
- **Integration tests** (RBAC, concurrency, summary parity) run against the
  seeded PostgreSQL via the API, and clean up any rows they create so repeated
  runs are stable.
- **Clock** is always `APP_NOW` (default `2026-11-11T15:00:00Z`); nothing reads
  the wall clock for business rules. The meeting timer is the one wall-clock
  concern and is not asserted on in the rule tests.
This note ships in `HOW_TO_RUN.md` / the README (ADR0014).

### 6. Failure artifact
Playwright is configured to **retain a trace on failure**. A documented command
(`npx playwright test e2e/_failure_artifact.spec.ts`, a spec with one deliberate
failing assertion, excluded from the normal run) produces a trace; one
`trace.zip` is committed under `frontend/e2e/artifacts/` as the required failure
artifact, viewable with `npx playwright show-trace`.

## Consequences

- The spec's three layers are covered by one documented command, on seed data
  and a fixed clock.
- The two-browser test exercises the real path end to end (start → join →
  advance → follow) and is the automated form of the manual proof from ADR0012.
- Playwright adds a frontend dev dependency and a one-time browser download; CI
  or a grader runs `npx playwright install chromium` first (documented).
- The E2E depends on the running seeded stack; `test_all.sh` brings it up, and
  ADR0014 folds this into the `docker compose` packaging.

## Verification

- `scripts/test_all.sh` runs pytest (all green) then the Playwright E2E (green)
  unattended.
- The two-browser test fails if the attendee does not follow within the timeout,
  so it genuinely guards real-time sync.
- The committed trace opens in the Playwright trace viewer.
